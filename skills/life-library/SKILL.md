# 人生库

用长期事实档案连接经历积累、方向探索和求职表达。主入口是「记一条」「补证据」「当前简历」「下一步」。使用者的数据独立于本 Skill 保存；不使用模型记忆代替档案。

## 开始使用

先定位用户已经指定的人生库；没有时选择当前工作区内不用于公开发布的 `life-library-data`，若工作区是公共源码仓库则先确定独立个人资料位置。数据目录不得位于本 Skill 安装目录内。先把数据位置解析成绝对路径，再调用脚本；不能切换到 Skill 目录后误把相对数据路径解析到安装位置。通过下方脚本初始化，已有库不会被重置。首次记录可先完成，只在方向分析需要时询问专业、入学年份、预计毕业年份、兴趣与就业/升学意向；未知字段留空，不从学校或专业猜测个人事实。

脚本路径以本 Skill 目录为基准，使用绝对路径调用；需要 Python 3.10+，不需要第三方库。根据环境选择 python、python3 或 py -3，中文 Windows 环境加 `-X utf8`：

```text
python -X utf8 <Skill绝对路径>/scripts/library.py init --root <数据绝对路径>
python -X utf8 <Skill绝对路径>/scripts/library.py check --root <数据绝对路径>
python -X utf8 <Skill绝对路径>/scripts/library.py render --root <数据绝对路径>
```

数据格式与命令见 [references/data.md](references/data.md)。每次实际修改前读取现有数据，保留并发改动。事实更正应在原记录追加 corrections，保留原话。更新后 check、render 并报告记录位置。页面是本地只读视图，记录和分析由对话驱动；不宣称网页可以直接写回文件或在后台自动刷新。

## 记一条

把用户原话写为记录的 `raw`，整理成标题、类型、发生时间、个人职责、结果、标签及待补项。发生时间与录入时间分开；只知道年份就记录年份，未知留空。不能用录入时间冒充发生时间。随手记录不追问完整问卷，缺项存入 `pending`。

默认 `private`，只有用户明确表示可用于简历，或明确要求将该条作为简历素材时才设 `resume`。仅分析 `resume` 记录生成简历与岗位建议，私密日记不送入 asu。新纪录使用 UUID，后续证据归到同一 ID。重复叙述先比对时间、标题和原话，疑似重复不要擅自合并。

原始说法、整理事实、岗位表达分别保存。`facts` 是可追溯的事实条目，状态分 `reported`（用户陈述）、`verified`（已阅读对应证据并核对）、`uncertain`（待核实）。有附件不等于已核实。指标保留数值、单位、基线、测量条件、样本范围和计算口径；缺失则标待补。个人贡献、团队成果、课程/个人/实习项目和 AI 辅助边界必须写清。

## 补证据

读取文件后用 `attach` 复制原文件到库内证据目录并计算 SHA-256，不移动原件，不只保存可能失效的外部路径。URL 也可作为来源，但注明访问日期与类型；未下载的网页不称为已归档。原始证据不覆盖，补充或更正追加到该经历。涉及成绩单、身份证等材料时，仅保留任务需要的内容；不默认把附件嵌入简历或上传。

## 方向与下一步

专业只是候选方向的起点。综合年级、兴趣、升学/就业意向、可投入时间和已允许用于求职的经历，给少量可调整方向，说明依据、未知条件和低成本验证方法；允许「尚未确定」。大一侧重探索和学习，大三以后依据意向收敛，不能把探索性推断写成真实市场结论。

岗位资料存为带来源及采集日期的快照；区分 JD 要求、招聘状态与明确公布的 HC 人数。未公布人数为 null。历史资料只能用于历史需求分析；「当前可投」「最新要求」必须核验官方来源并记录核验日期。没有网络或来源就明确限制，不生成假链接和假招聘状态。

分析多个相关岗位的重复要求；把硬性学历/届别门槛与可培养能力分开，不把单条 JD 当普遍市场规律。缺口表使用「已有证据 / 证据不足 / 尚无经历」，不用无依据的分数或录用概率。

每个建议写明对应需求或探索假设、当前缺口、具体行动、预计投入（标明估算）、交付证据与验收方式。用户只要记录时不额外启动辅导；请求下一步时优先给最值得做的少量行动，不自动建日程或提醒。

## 当前简历与 asu

读取可用的 `asu` 技能，仅传入选定方向、来源明确的 JD、`resume` 记录及事实边界。用户只要求简历时仅生成简历相关输出，不附带默认 HR 消息。asu 不可用时按「动作—结果—证据—个人边界」整理，不假称已调用。

每条 bullet 存入 `resume.bullets`，必须引用事实 ID；uncertain 事实不进入简历，reported 事实必须让用户能看到其证据状态。每次强主张都检查原始证据和个人贡献；不编造数字，不把团队贡献写为个人主导。生成表达只更新 resume，不覆盖 raw 或 facts。

刷新当前草稿后可打开 `index.html`。用户明确要求留存投递版时执行 snapshot，固化当前 Markdown 简历、来源数据和对应附件。目标公司与岗位在用户提供后填入；留档不等于实际投递。快照不随草稿更新。导出/备份整个资料库包含私密记录，不能当公开简历发送。

## 验收边界

检查记录不丢原话、来源引用可解析、附件哈希匹配、私密和 uncertain 事实未进入简历、快照不会被后续渲染改写。报告真实执行情况，不把用户陈述称为已核实，不把生成静态视图称为持续运行服务。
